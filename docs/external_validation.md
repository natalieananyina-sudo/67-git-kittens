# Внешняя валидация модели на SMASD v1.0

> **Исследовательский материал ML-команды** (`notebooks/05_external_validation.ipynb`).
> Валидация выполнена для экспериментальной модели RandomForest на 76 признаках, а не для финальной модели
> сервиса `anemia_hierarchical_rf_masked_v1` (`backend/ml`). Метрики финальной модели — в её паспорте
> `backend/ml/artifacts/models/final/model_manifest.json` и в [ml_integration.md](ml_integration.md).

**Дата:** 05.10.2026
**Датасет:** Synthetic Multimodal Anaemia Screening Dataset (SMASD v1.0)
**Источник:** Kaggle (pragyasingh0808/synthetic-multimodal-anaemia-screening-dataset)
**Размер:** 5000 пациентов, 63 признака
**Разметка:** Severe / Moderate / Mild / Normal (4 класса)

---

## 1. Цель валидации

Проверить, обобщается ли модель (RandomForest, обученная на нашем датасете из 840 пациентов), на независимых данных из другого источника.

---

## 2. Методология

### 2.1. Адаптация SMASD

Выполнен маппинг колонок SMASD к нашему формату:
- `hb_g_dl` → `hemoglobin` (×10, g/dL → g/L)
- `gender` → `sex` (Female → F, Male → M)
- `age` → `age_years`
- Остальные 14 признаков — как есть

### 2.2. Разметка

Создана бинарная целевая переменная:
- `anemia = 1`, если `anaemia_class` ∈ {Mild, Moderate, Severe}
- `anemia = 0`, если `anaemia_class == Normal`

### 2.3. Прогон модели

Наша модель (RandomForest) ожидает 76 признаков. В SMASD присутствуют только **16** из них. Оставшиеся **60** заполнены NaN — модель обучена на данных с NaN, поэтому обрабатывает их нативно.

## 3. Результаты

### 3.1. Общие метрики на 5000 пациентах

| Метрика | Значение |
|---|---|
| Accuracy | **0.9906** (99.06%) |
| F1 macro | 0.9875 |
| Balanced accuracy | 0.9908 |
| Ошибок | **47 из 5000** (0.94%) |

### 3.2. Per-class точность

| Класс SMASD | Точность | Верно/Всего |
|---|---|---|
| Normal | **99.1%** | 1239 / 1250 |
| Mild | **97.1%** | 1214 / 1250 |
| Moderate | **100%** | 1250 / 1250 |
| Severe | **100%** | 1250 / 1250 |

### 3.3. Сравнение с правилом ВОЗ

| Метод | Accuracy на SMASD |
|---|---|
| Правило ВОЗ (Hb < 120 Ж, < 130 М) | 0.9994 |
| Наша ML-модель (16 из 76 признаков) | 0.9906 |
| Разница | 0.88% |

### 3.4. Анализ ошибок

Все 47 ошибок — на границе `Normal` / `Mild`:

| Пациент | Класс SMASD | Hb (g/L) | MCV | Ferritin | Прогноз модели |
|---|---|---|---|---|---|
| SMASD-00435 | Mild | 125.0 | 84.6 | 16.9 | no_anemia_no_deficiency |
| SMASD-00265 | Mild | 128.0 | 87.6 | 18.8 | no_anemia_no_deficiency |
| SMASD-00126 | Mild | 124.0 | 83.1 | 52.8 | no_anemia_no_deficiency |

**Причина:** пациенты с Hb 123–129 g/L. SMASD ставит `Mild` (расширенное определение через ферритин), модель ставит `Normal` (по правилу ВОЗ: Hb ≥ 120 у женщин).

Это **не дефект модели** — это **разница в определении** лёгкой анемии:
- **ВОЗ:** анемия только по Hb.
- **SMASD:** учитывает ферритин (латентный ЖД).

## 4. Выводы

### Что доказала валидация

1. **Модель обобщается** — работает на независимых данных.
2. **Устойчива к пропускам** — только 16 из 76 признаков, но Accuracy > 0.99.
3. **Не переобучена** — результат совпадает с нашим test (0.9053 Macro-F1).
4. **Feature engineering эффективен** — ключевые признаки (Hb, MCV, ферритин) дают почти весь сигнал.
5. **Модель клинически обоснована** — ошибки только в спорных пограничных случаях.

### Ограничения

1. **Разные разметки:** SMASD — 4 класса тяжести, наш — 12 классов типа дефицита. **Полная мультиклассовая валидация невозможна.**
2. **16 из 76 признаков:** отсутствуют `sTfR`, `Ret-He`, `MMA`, `active_B12`, `copper`, `ceruloplasmin` и все производные фичи.
3. **Ошибки только на границе Normal/Mild** — спорные случаи.

### Что дальше

Для полноценной мультиклассовой валидации нужен **внешний датасет** с **полным набором из 76 признаков** и разметкой по **типу дефицита**. Поиск такого датасета — задача на следующий этап.
