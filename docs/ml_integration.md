# ML-модель: что подключено и как

## Модель

| | |
| --- | --- |
| Название, версия | `anemia_hierarchical_rf_masked_v1`, 1.0.0 |
| Архитектура | Hierarchical Random Forest (500 деревьев) + panel masking |
| Что предсказывает модель | `deficiency_cause` (причина); `anemia_class` формируется детерминированно |
| Test-метрики (отложенная выборка) | macro-F1 0,8835 · balanced accuracy 0,8768 · macro precision 0,9096 · macro recall 0,8768 |
| Зависимости | Python 3.12, scikit-learn 1.9.0, pandas 3.0.3, numpy 2.4.6, joblib 1.5.3 |
| Паспорт | `backend/ml/artifacts/models/final/model_manifest.json` (в том числе SHA-256 файла модели) |

Модуль передан ML-командой и лежит в `backend/ml` **без изменений** (удалены только кэш-файлы `__pycache__`).
Его собственная документация — [backend/ml/README_ML.md](../backend/ml/README_ML.md).

## Связь с исследовательской частью репозитория

В `notebooks/` и `src/` лежит исследовательская работа ML-команды: EDA (`01_eda`), признаки (`02_features`),
сравнение моделей (`03_modeling`), SHAP-интерпретация (`04_interpretation`), внешняя валидация
(`05_external_validation`), а также `src/train.py` — обучение экспериментальной модели RandomForest
на 76 признаках (`models/model.pkl`). Эти модели сервис **не использует**: в сервис поставлена финальная
модель `anemia_hierarchical_rf_masked_v1` вместе с runtime-кодом (`backend/ml`). Код обучения финальной
модели в репозиторий пока не добавлен; её паспорт с test-метриками — `model_manifest.json`.

Метрики экспериментов в ноутбуках (например, macro-F1 0,9053 у RandomForest на 76 признаках) и метрики
финальной модели (macro-F1 0,8835) относятся к разным моделям с разными признаками и способом обучения
(финальная обучалась с маскированием панелей, panel masking), поэтому сравнивать их напрямую не стоит.
Подробности — у ML-команды.

## Как согласованы инструкции ML-команды и бэкенда

| Указание ML-команды | Как сделано в сервисе |
| --- | --- |
| Использовать `AnemiaInferenceService` из `src.ml` | `backend/app/engine/predictor.py`: `MlModulePredictor` добавляет `backend/ml` в путь импорта и вызывает `from src.ml import AnemiaInferenceService` |
| Вход — `dict`: `age_years`, `sex` = `F`/`M`, лабораторные показатели по названиям `src/ml/config.py`; отсутствующие можно не передавать | `to_model_input()`: ключи — коды столбцов датасета, значения уже переведены в единицы датасета, пустые не передаются, пол `female`/`male` → `F`/`M` |
| Правило анемии, preprocessing, postprocessing, `anemia_class`, проверку достаточности **не дублировать** | Бэкенд их не считает. Проверка формата (`validation.py`) больше не требует пол и гемоглобин: при их отсутствии модуль сам вернёт `insufficient_data`. Прежние правила бэкенда (`rules.py`, собственное сопоставление классов) удалены |
| `anemia_class` не пересчитывать, брать из ответа | Ответ модуля передаётся во фронтенд целиком в поле `ml_result`; поля `anemia_class`, `deficiency_cause`, `anemia`, `screening_status` берутся из него |
| `model_score` и `deficiency_cause_scores` — не вероятности | Интерфейс показывает их полосой и числом 0..1 с подписью «технические оценки модели, а не вероятности диагноза»; процентов нет (проверяется тестом) |
| Использовать именно `pipeline.joblib` из поставки | Перед загрузкой SHA-256 файла сверяется с паспортом; при несовпадении модель не загружается |
| Зафиксированные зависимости | `backend/requirements.txt` подключает `-r ml/requirements-ml.txt`; Docker-образ на Python 3.12 |
| Проверка: `python example_inference.py` | Входит в `scripts/setup.sh` и `scripts/test.sh`; тот же пример прогоняется через весь бэкенд в `tests/test_ml_integration.py` |

Что осталось за бэкендом: чтение CSV/XLSX, проверка формата ячеек, перевод единиц, русские подписи значений
модели (`backend/app/engine/labels.py`), тексты заключений эксперта (`conclusions.py`), API и интерфейс.

## Статусы ответа модели

| `status` | Что показывает интерфейс |
| --- | --- |
| `signal_detected` | Итоговый класс, причина, scores модели и рекомендации |
| `no_signal_detected` | «Нет анемии и исследуемых дефицитов», повторное обследование через год |
| `insufficient_data` | «Недостаточно данных для заключения» и причина: нет пола, нет гемоглобина или полностью отсутствуют две и более панели анализов (кроме общего анализа крови); перечислены недостающие панели |

## Производительность

Один вызов модели — около 0,1 с (500 деревьев). Для файла с многими пациентами `predict_many()` вызывает лес
**один раз** на все строки, а затем для каждой строки — обычный `AnemiaInferenceService.predict`, у которого
классификатор заменён таблицей уже посчитанных ответов. Логика модуля не повторяется, а результат совпадает
с поштучным вызовом (тест `test_batch_equals_single`). Остаётся подготовка данных внутри модуля
(около 10–20 мс на строку), поэтому лимит одной загрузки — 1000 строк; 600 строк обрабатываются за 10–15 с.

## Режимы и демо-резерв

`ML_MODE` в `config/backend.env`:

* `auto` (по умолчанию) — финальная модель; если она не загрузилась (нет файла, не совпала SHA-256, не та версия
  библиотеки), включается демо-резерв, а интерфейс показывает предупреждение «Демонстрационный режим» с причиной;
* `model` — только финальная модель: если она не загрузилась, бэкенд не запускается;
* `demo` — всегда демо-резерв (разработка интерфейса без модели).

Демо-резерв (`DemoPredictor`) подменяет **только классификатор**: вместо Random Forest — баллы по лабораторным
критериям (ферритин, TSAT, sTfR, B12, holoTC, MMA, фолат, B6, медь, церулоплазмин, СРБ, СОЭ). Проверка данных,
правило анемии, ограничение допустимых причин и итоговый класс и в этом режиме выполняет код ML-модуля.
Текущий режим: `GET /api/v1/health` → `model.kind` (`ml_model` или `demo_fallback`).

## Замена модели на новую версию

1. Замените папку `backend/ml` новой поставкой ML-команды (с новым `model_manifest.json`).
2. Если изменились зависимости — `scripts/setup.sh` (или пересборка Docker-образа).
3. `scripts/test.sh`. Тест `test_every_ml_value_has_russian_label` подскажет, если появились новые классы
   или причины без русских подписей (их нужно добавить в `labels.py`).
4. Пересоберите демо-наборы: `backend/.venv/bin/python scripts/generate_demo_data.py`.
