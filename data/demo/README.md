# Демонстрационные данные

Все наборы сгенерированы скриптом `scripts/generate_demo_data.py` на основе исходного датасета:
каждая строка — слегка зашумлённая (±1,5–3 %) копия реальной строки того же класса с пересчитанными
производными индексами (MCV, MCH, MCHC, TIBC, TSAT). Набор пропусков сохранён, наличие анемии по порогу ВОЗ
не меняется. ID новые, персональных данных нет. Формат столбцов — как в исходном датасете.

| Файл | Строк | Назначение |
| --- | --- | --- |
| `01_showcase_all_classes.csv` | 24 | Витрина: по 2 пациента каждого из 12 классов. Отобраны так, что ML-модель классифицирует их верно |
| `02_clinic_day_representative.csv` | 60 | Обычный приём: распределение классов как в исходных данных, **без отбора**. Около трети строк модель отмечает «недостаточно данных» (как и в исходном датасете); среди остальных совпадение с истинным классом около 95 % |
| `03_screening_large.xlsx` | 600 | Массовый скрининг в формате XLSX, без отбора: производительность (10–15 с) и поддержка XLSX; около 30 % строк — «недостаточно данных» |
| `04_with_format_errors.csv` | 15 | 8 корректных строк и 7 с типичными проблемами (5 ошибок формата, повтор ID, пустой гемоглобин → «недостаточно данных»); есть лишний столбец `comment` |
| `05_other_units.csv` | 10 | Единицы в заголовках: гемоглобин г/дл, ферритин нг/мл, B12 пмоль/л, фолат нмоль/л, креатинин и СРБ мг/дл |
| `single/01…07_*.csv` | 1 | Файлы одного пациента для режима «Один пациент» (норма, ЖДА, латентный дефицит железа, B12 без анемии, сочетанный, воспаление, медь) |
| `single/08_with_errors.csv` | 1 | Один пациент с ошибками формата: текст вместо ферритина, «<0,5» вместо СРБ |
| `single/09_insufficient_data.csv` | 1 | Один пациент, для которого модель вернёт «недостаточно данных» (нет двух панелей анализов) |

Папка `answers/` — ключи ответов: истинный класс каждого пациента, статус и класс, которые выдала модель при
генерации, и список заложенных проблем для файла `04`. Ответы в загружаемые файлы не включены.

Важно: модель обучалась на исходном датасете, а демо-наборы сделаны из его строк, поэтому совпадение здесь выше,
чем будет на новых данных. Честная оценка качества — test-метрики в паспорте модели
(`backend/ml/artifacts/models/final/model_manifest.json`, macro-F1 0,88).

Пересборка (например, после замены модели):

```bash
cp путь/к/deficiency_anemia.csv data/raw/      # исходный датасет; в git не хранится
backend/.venv/bin/python scripts/generate_demo_data.py
```
